Folder layout for new saves

New records go to progress/<provider>/<problem>/<attempt>/ and imports/<provider>/<problem>/<slot>/<hash>/ unless you choose the problem-first layout for this repository. Problem-first writes <problem>/passed-<attempt>/, <problem>/failed-<attempt>/ and <problem>/imported-<record>/, and dedicates this repository to HDLBits; a different provider is refused rather than added to it.

The choice applies only to records saved after it. Nothing already published is moved, renamed, or deleted, the repository marker file is not rewritten, and work already queued keeps the layout it was created with. Both layouts are read back on this device's “Saved progress from GitHub”.

Failed attempts

Failed attempts stay on this device by default. Turning this on publishes each new failed attempt to your selected public repository: the exact source you submitted, the recorded outcome, and a submission report holding the result's status line, any supported compiler or simulator messages, and each timing diagram the result drew, stored as a static PNG beside the report. Anyone can read them.

Lesson explanations, reference solutions, and expected-output tables are never copied or published. Diagrams are published with HDLBits named as their source and a link to the problem page; HDLBits does not endorse this extension. Turning this on publishes nothing captured before now, and turning it off stops new failed attempts without removing anything already published. Each older failed attempt is published only when you choose it on the attempts page.

Verification checks current identity, installation access, permissions and branch. Branch rules or later revocation may still reject a write.
