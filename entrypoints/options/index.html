Local queue and history

Disconnecting GitHub or restarting the browser retains captured source, pending delivery jobs, and saved history. Retained jobs stay bound to their original GitHub account, App, installation, repository, and branch. Changing the selected destination never redirects a job to it.

Queued work interrupted by a temporary outage, a rate limit, or a stopped worker resumes on its own, on a bounded schedule of at most five spaced attempts. Each attempt reverifies the original account and destination and proves the complete remote record before writing, so a resumed job cannot publish twice. Work blocked by authorization, permission, validation, or branch policy, and work that has spent its attempts, waits for you.

When GitHub states a time to wait, nothing is sent before it: that wait applies to every queued job for the same account and App, to newly accepted attempts, and to “Check GitHub and retry delivery”, which reports the time instead of sending early. A wait longer than this browser can schedule is explained and left for you. If automatic scheduling itself fails, this page says so rather than promising an attempt that cannot happen.

After a browser restart or a disconnect, resumption waits for you to reconnect the original account and App and to verify the original destination again; credentials are never restored. Requests already issued may complete even after disconnect.

Undelivered work is stored only in this browser profile. Clearing extension storage, removing the extension, or losing this device loses attempts that were never saved to GitHub.

“Discard local attempt” removes an unsaved attempt's captured source and delivery job only from this browser. This cannot be undone and does not delete anything on GitHub or prove that publication never happened. Saved receipts are not discardable here.

Earlier HDLBits solutions

Solutions finished before Progress Sync was installed can be imported from HDLBits' own “Load a previous submission” control, without resubmitting them. That control offers only the last successful stored submission per problem, and only where the page has one; a solved badge on its own is not a source of code.

Imports are recorded and published as unverified — HDLBits' stored copy and the site's own claim, not an acceptance Progress Sync observed. Source is taken only from a load HDLBits reports as successful; any other status is listed as a skipped problem, with the value kept as provenance. Imported records live under a separate imports/ path and are never read back as accepted captures.

Discovery reads through an HDLBits problem page you already have open, using whatever site session this browser already has. It never opens or navigates a page, never touches your editor contents or HDLBits' native solved state, and never sends site cookies to GitHub. Nothing is published until you confirm each import individually. One pass reads up to 100 solved problems and 2 MB of source; if the page lists more, the status line says how far it got and finding earlier solutions again continues from there.
